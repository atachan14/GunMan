# 配布とオンライン

[ドキュメント一覧へ](../README.md)

## 配布・参加方法（合意済み）

| 項目 | 方針 |
| --- | --- |
| 正式版 | Steamでの配布を目指す |
| テスト版 | itch.ioで配布する |
| ブラウザ | 可能なら対応したい。早期に動作検証する |
| v1の参加方法 | 部屋コードを相手に共有して参加する1対1対戦 |
| ランクマッチ | v2以降の検討事項 |

部屋を作成してコードを表示し、相手がそのコードを入力して合流する流れです。コードの共有はゲーム外で行う想定です。

## 技術方針（暫定）

- Netcode for GameObjects（NGO）を想定して進めます。
- Unity Multiplayer ServicesとRelayは接続・中継の候補です。採用は未確定です。
- Steamworksを対戦の必須条件にしません。
- 早期テストで操作感などに問題があれば、原因と改善可能性を確認し、必要に応じて別方式を検討します。

部屋への参加方法、通信手段、ゲーム状態の同期、命中結果を確定する権限は別の設計事項です。NGOの暫定採用で判定権限まで決定したことにはしません。

## 早期検証

CPU対戦の1ラウンドが動いた段階で、完成前に通信テストを挟みます。初期は開発者1人・PC1台で2つの実行環境を接続し、片方をテスト用自動操作にします。遊べる段階で友人との実機・対人テストを追加します。具体的な順序と確認条件は[開発順序](../design/development-plan.md)を参照してください。

- 2人接続で初期化と対戦開始の同期を確認します。過去にStart()の同期ミスで構造が崩れた経験を踏まえます。
- 遅延を加え、ホストとクライアントを交代して照準・抜銃・回避・発砲の反応を比較します。
- クライアントのカメラや操作表示が通信の往復待ちで重くならないかを確認します。
- 見た目の操作感に加え、命中・回避・発砲順の結果に不自然な差がないかを確認します。
- ブラウザでの2人接続と、右クリックでの抜銃・マウス照準などの操作を確認します。

## 未決定

- 命中結果を確定する判定権限と、判定で参照する相手の姿勢の時刻。
- 予測・補正やラグ補償の方式、許容する遅延とテストの合格基準。
- [ゲームルール](game-rules.md)の時刻順判定を実現する共通時刻への換算・精度・入力検証。同時射撃・同時抜銃の具体的な識別方法。
- 遅れて到着する射撃の受付範囲と結果の確定待ち。期限前の発砲が期限後に届く場合も含めて設計します。
- ブラウザ版とデスクトップ版の相互対戦を必須にするか。
- 切断、ホスト退出、接続失敗、再接続時の扱い。
- 中継サービス等の運用費の上限と、対応するブラウザ・環境。
