# CPU対戦から始める実装設計

[ドキュメント一覧へ](../README.md) / [開発順序](development-plan.md)

この文書は既存コードを踏まえた実装案です。記載する新しい型は未実装で、細部は実装時に調整します。ルールの正本は[ゲームルール](../specs/game-rules.md)、表示の正本は[進行と演出](../specs/round-flow.md)です。

## 責務

| 担当・型の案 | 所有するもの・行うこと |
| --- | --- |
| MatchController | 参加者2人、ラウンド番号、合計得点、次ラウンドの準備 |
| RoundController | 開始時刻・期限、入力受付、決着、演出完了待ち。ゲーム状態を変更する入口 |
| PlayerState | PlayerId、抜銃・発砲時刻、後抜き、被弾、回避残数、微回避・回避の進行 |
| 入力アダプター | 人間・CPUの操作を共通の入力データに変換。状態や得点を直接書き換えない |
| PlayerActor | 各キャラクターの姿勢、銃口、当たり判定を更新。ルール側が許可した操作を適用 |
| ShotResolver | 射線と部位Colliderから有効な命中を収集し、貫通・停止・得点部位を解決 |
| 表示担当 | ローカルプレイヤーのカメラ、UI、被弾・BulletTime演出。結果を表示し、演出完了を通知 |

まず必要な担当だけを追加します。MatchControllerは5ラウンド化の段階で追加でき、最初から汎用的なサービス基盤を作る必要はありません。

## 状態の分け方

- ラウンド進行: Preparing、Opening、Duel、Resolving、Result。
- プレイヤーの状態: 銃の保持、発砲済み、被弾済み、回避の進行を別々に保持。
- 表示: Opening、TPS、FPS、BulletTime、被弾表示、待機。表示状態だけで行動可否を決めない。

Resolvingは決着済みで演出完了を待つ段階です。片方が外してBulletTimeに入っただけなら、ラウンドはDuelのままです。

キャラクター操作可能条件は「Duel中かつ未発砲かつ未被弾」。新たな操作を止めても、開始済み回避やニュートラルへの復帰は別に更新します。被弾でそれらを中断します。発砲済みと被弾済みは両立できるため、相撃ちや発砲後の被弾も表現できます。

## 入力と処理順

入力はPlayerId、ラウンド識別子、シーケンス番号、時刻、操作内容を持つ案です。連続する照準・微回避入力と、抜銃・発砲・回避開始のイベントを区別します。

- 人間の画面座標はローカル側で照準目標へ変換します。相手側のCamera.mainや画面解像度で同じ座標を再解釈させません。
- CPUは一定時刻の抜銃・照準・発砲から開始します。同じ入力受付と行動制約を通し、命中や得点を直接発生させません。
- 既存のIPlayerInputを移行の入口にし、押下・解放・保持状態とイベント時刻を扱える形へ拡張します。フレームごとのboolだけでは同フレーム内の複数イベントの順序を保存できません。
- ネット経由の入力も同じルール処理へ渡します。ただしクライアントが送った時刻・照準・抜銃可能判定を無条件には信用しません。

ローカル試作では両者の入力を収集し、時刻順に処理します。同時抜銃は変更前の状態から双方を評価し、同時射撃も双方の命中評価を終えてから結果を適用します。同時に片方だけが命中した場合は、その側の勝利です。

照準・回避による姿勢の更新、Colliderへの反映、射撃判定の順序を明示的に管理します。現在のUpdateとLateUpdateの実行順に任せて、前フレームの銃口や姿勢で判定しないようにします。過去時刻に対する正確な姿勢再現はオンライン検証で扱います。

## 射撃結果

ShotResultは射撃の識別子、射手、採用時刻、射線、有効命中、停止位置、得点対象部位、倍率、得点を保持する案です。採点済みの結果は表示から再計算しません。

ShotResolverは自分自身と演出用Colliderを除外し、射線上の命中を距離順に評価します。停止部位までの有効命中に対して、仕様の最高得点・股間例外を適用します。環境障害物や同距離の境界の優先順位は実装時に明示します。

時刻の異なる射撃は先の有効な命中を優先します。得点反映は識別子で一度だけにし、通知の重複や演出完了通知で増えないようにします。

## 時計とオンラインの暫定案

ローカルの対戦時計は演出のスロー速度から独立させ、テストから時刻を指定できる形にします。イベント時刻と姿勢更新のステップは分け、数値の桁数だけで入力精度を保証しません。

最初のNGO接続テストはホストを判定役にする案です。クライアントは自分の照準などを即座に表示し、命中・得点の確定は判定役から受け取ります。ホストも同じルール処理を通しますが、これだけでホスト有利が解消するとは考えません。

通信テスト前に次を具体化します。

- 入力時刻の共通基準への換算と許容範囲、同時判定の精度。
- 遅れて届く入力をどこまで受け付け、いつ結果を確定するか。
- 射撃時刻に対応する姿勢の履歴と、クライアント表示との差の補償。
- 予測が外れた場合の保持・回避・発砲表示の補正。

ローカル試作の結果をネット対戦の公平性の証明には使いません。NGOの採用判断は遅延を加えた実測で行います。

## 既存コードの移行

| 現在のコード | 移行方針 |
| --- | --- |
| RoundManager | TPS/FPSを含む全体Modeへの依存を、ラウンド進行と各PlayerStateへ段階的に置き換える |
| OpeningActor | 各端末のStart起点ではなく、準備完了と共通の対戦開始時刻に従う |
| HumanPlayerInput / IPlayerInput | 共通入力の入口として利用し、時刻・保持状態を追加。導入済みInput Systemへの移行を検討 |
| ButtonReceiver | 直接Modeを変更せず抜銃要求を送る。右ボタン解放時のDropGun呼び出しを廃止 |
| AimReceiver | 各PlayerStateと入力を参照。姿勢の計算を残し、Camera.main等のローカル表示への依存を整理 |
| WiggleController | Input直読みを廃止し、操作禁止・姿勢維持・復帰・被弾中断を状態から反映 |
| CameraController等 | ローカルプレイヤーだけに接続し、相手の抜銃で自分のカメラが切り替わらないようにする |
| ReplayManager | v1の独立リプレイは実装しない。BulletTime用記録が必要なら用途を限定して別途設計 |

既存シーン・Prefabの参照を確認してからコンポーネントを移行し、.metaのGUIDを維持します。スクリプトや列挙値を一括削除して参照を壊さないよう、段階ごとにUnity上で確認します。
