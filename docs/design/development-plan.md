# 開発順序と確認条件

[ドキュメント一覧へ](../README.md) / [実装設計](architecture.md)

CPU対戦を先に作り、完成前に通信の検証を挟みます。初期検証は開発者1人・PC1台で行い、遊べる段階で友人による実機・対人テストを追加します。以下は実装予定で、完了記録ではありません。

## 1. ローカルCPU対戦の1ラウンド

最初の実装単位は次の順です。

1. プレイヤー別の状態と入力受付を構築し、抜銃後に手放せない操作を接続する。既存のクラス構造は必要に応じて置き換える。
2. 簡単なCPU入力を追加し、人間と別のキャラクターを同じルールで操作する。一定時間後の抜銃・照準・発砲で十分。
3. 部位Collider、貫通判定、得点計算、発砲済み・被弾済みの制御を追加する。
4. 開始、時間切れ、決着、簡易Result、次の検証のためのリセットまで接続する。

BulletTimeはこの段階では簡易表示と完了通知で置き換え、本演出は後で作ります。制限時間・CPUの行動時刻はInspector等で調整できる試作用設定にします。

確認条件:

- 人間とCPUのどちらも抜銃・1発制限・被弾後の操作禁止を守る。
- 自分と相手の抜銃状態、カメラ、入力が混ざらない。
- 発砲後の回避継続、微回避維持・復帰、被弾中断が仕様どおり。
- 貫通・停止・股間例外・後抜きの計算が仕様の例と一致する。
- 命中、両者外れ、時間切れ、相撃ちで結果が一度だけ確定する。
- リセットで弾数・得点・姿勢・入力イベントが前ラウンドから残らない。

得点・状態遷移・同時判定はEditModeテストで確認し、姿勢・Collider・UIはPlayModeまたはUnity上の操作で確認します。

## 2. 1人・2接続の早期通信テスト

本格的なCPU難易度や演出を作り込む前に実施します。人間が2人いる必要はありません。

- 2つの実行環境を同じPCで起動し、一方をホスト、他方をクライアントにする。Editorとビルド、またはMultiplayer Play Modeを候補とする。
- 自分は片方を操作し、もう片方はテスト用の一定動作を行う。自動操作も接続先から通常の入力経路で送る。
- ホストとクライアントの操作担当を入れ替え、同じシナリオを繰り返す。
- 遅延・揺らぎ・欠落を加えて開始同期、操作反応、抜銃順、射撃順、期限付近の入力を確認する。
- ブラウザの接続とマウス操作も小さなテストで確認する。バックグラウンドの停止・入力フォーカス・端末負荷と通信遅延を混同しない。

各端末の入力時刻、判定役の受付時刻、採用時刻、結果、表示時刻を記録して比較します。表示の応答性と判定の公平性は別々に評価します。具体的な遅延条件と合格基準はテスト実装前に決めます。

NGOの追加機能が必要か、設計変更または別方式を検討するかをここで判断します。公開用の部屋作成画面や本格AIは前提にしません。

## 3. CPU対戦を1試合にする

- 5ラウンドの合計得点、次ラウンド初期化、試合結果を完成させる。
- CPU対戦の準備操作・再戦・退出を具体化する。
- CPUの狙い・抜銃・回避と難易度を調整する。
- BulletTimeと被弾演出、時間切れの演出完了待ちを実装する。

CPU相手に1試合を繰り返し遊べ、対戦時間と演出時間を別々に調整できることを確認します。

## 4. オンラインの導線と公開テスト

- 部屋コードによる作成・参加、退出・切断、再戦を整える。
- 選定した配布形式でビルドし、実際の別端末・別回線で接続を確認する。
- 友人とのテストで操作感、駆け引き、5ラウンドのテンポを確認する。

ローカルの2接続テストだけでは、実回線や人間同士の遊びやすさまで確認済みとはしません。
