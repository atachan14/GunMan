# 🧩 基本コンセプト
1対1の対戦型TPS/FPSシューティング
TPS視点で銃を掴んで、FPS視点で狙撃
銃を抜くタイミングと回避の読みあい、精度が勝負を分ける、駆け引き系のゲーム性

# ラウンドの流れと操作仕様

- 対戦中、行動可能な間のキャラクター操作（発砲後・被弾後・決着後は不可）
    - WASD（無制限）
        - 微回避
    - WASD+Space（ラウンド毎に1回のみ）
        - 回避
- 発砲後の操作とモーション
    - 命中・外れに関わらず、発砲後はそのラウンドのキャラクター操作を受け付けない。照準・銃の持ち替えや手放し・新たな微回避や回避はできない。
    - 発砲時点で既に開始している回避モーションは、発砲を理由に停止せず最後まで継続する。入力による方向変更や延長はできない。
    - 未決着の間は継続中の回避による姿勢・当たり判定の変化を相手の射撃判定にも反映する。見た目だけのモーションにはしない。
    - BulletTimeのカメラ移動・ズームはキャラクター操作とは別に扱い、引き続き可能とする。
    - 回避途中で被弾した場合の、回避モーションと被弾演出の切り替え方は未決定。

0. Opening(演出)

1. Duel
    1. TPS
        - 視点
            TPSAnchorから原点を見るカメラ。
            TPSRootの回転に従って円周上を周って、徐々に自キャラと相手キャラが被さっていく。
        - マウス移動
            - MouseNaviがマウスに追従。
            - MouseNaviの位置に向かって腕を伸ばし続ける。
            - MouseNaviの位置（OnGun,OnArmReach,TooFar）に応じてMouseNaviの色変更。
        - （OnGun時）右クリック押しっぱなし
            - 銃をHandPointの子にしてFPSモードに移行

    2. FPS
        - 視点
            EyePointからMuzzlePointを見るカメラ
            腕が動く→銃が動く→視点が動く
        - マウス移動
            - 操作量に応じて腕が動く
        - 右クリック離す
            - 銃を親から放してTPSモードに戻る
        - 左クリック
            - 未発砲かつ行動可能・未決着の場合のみ発砲してShotFireに移行。1人1ラウンド1発のみ。

2. ShotFire（一瞬）
    - ヒットスキャン方式を採用する。発砲時点の射線で命中・命中部位・得点を決定する。
    - 銃口（MuzzlePoint）から射撃方向へRaycastを飛ばして、相手に当たるか確認する。
    - 回避は相手の発砲前に射線から外れることで成立する。相手の発砲後の弾の飛行演出中に、その射撃を回避する方式にはしない。
    - オンラインで参照する相手の姿勢の時刻、判定権限、同時発砲の扱いは別途決める。
        - 当たる場合
            先に有効な命中を成立させた側のラウンド勝利とする。被弾側は部位を問わずラウンド敗北・行動不能となり、GotShotに移行する。撃った側はBulletTimeに移行する。
        - 外れた場合
            発砲済み・命中なしの射撃結果を共有し、撃った側はBulletTimeに移行する。相手はGotShotに移行しない。
            相手が未発砲なら対戦を継続する。両者が発砲して外れた場合は、そのラウンドを引き分けとする。

    1. BulletTiem（撃った側,弾の当たり外れに関わらず実施）※実装後回し
        - 視点
            BulletBackからBulletFrontを見るカメラ
            スロー再生（内部的にはリプレイ的な処理だけど、プレイヤー的にはリアルタイムっぽい）
        - マウス移動
            - 操作量に応じてBulletBackが動く
        - マウスホイール
            - ズーム
        弾の飛行は確定済みの射撃結果を見せる演出とする。演出中の操作で命中結果は変わらない。
        得点は射撃結果の確定時に加算し、弾が相手に当たる演出のタイミングでは獲得スコアを表示する（重複加算しない）。
        当たる当たらないに関わらず、通り越して数秒でリプレイ待ちに移行
        自分の射撃が外れて対戦が継続している間にBulletTime中の自分が撃たれた場合は、その命中で自分のラウンド敗北となる。通常通りの演出を行った後にカメラが振り返り、撃たれている自分を映してリプレイ待ちに移行する。

    2. GotShot（撃たれた側,弾を当てられた場合のみ実施）
        - 視点
            TPSモード同様
        - 命中部位を問わず、そのラウンドは敗北・行動不能。被弾演出の終了を待たず、被弾成立時から対戦操作を受け付けない。
        自キャラが倒れる演出後、リプレイ待ちに移行

3. リプレイ待ち
    ラウンドの勝敗または引き分けが確定し、両者がリプレイ待ちになるとリプレイに移行する。
    片方だけが外して待機している間は、相手の射撃結果による決着を待つ。未発砲のまま進行しない場合の制限時間・終了条件は未決定。

4. リプレイ
    勝者が操作の主導権を持ち、共通のリプレイを見る。
    引き分け時の操作の主導権は未決定。
    両者がリプレイ終了操作で省略可能。
    リプレイを終えるとResultに移行。

5. Result
    ラウンド毎の両者のスコアと合計スコアを表示する。
    規定ラウンド数に達していない場合は、お互いにボタンクリックで次のラウンドに移行する。
    最終ラウンド後は合計スコアを比較して試合結果を表示する。試合終了後の再戦・退出の流れは未決定。


# ✅ スコア・判定
- ラウンド勝敗
    - 弾は1人1ラウンド1発のみ。外してもそのラウンドでは再発砲できない。
    - 相手に先に有効な命中を成立させた側が勝利する。先に発砲しても外れた場合は勝利にならない。
    - 両者が発砲して外れた場合は引き分けとし、両者ともそのラウンドの獲得スコアは0点とする。
    - どの部位でも被弾した側はそのラウンドに敗北し、行動不能となる。
    - 決着後の新たな射撃で勝敗や得点を変更しない。
    - 部位別得点とは別にラウンド勝敗を決める。股間への命中もラウンド勝利となるが、得点にはペナルティを適用する。
    - 同時命中の扱いは未決定。
- 試合全体の勝敗
    - 規定ラウンド数を戦い、全ラウンドの合計スコアが高い側を試合の勝者とする。ラウンド勝利数では決めない。
    - 引き分けのラウンドも実施ラウンド数に含める。
    - 最終合計スコアが同点の場合は試合も引き分けとする。延長戦は行わない。
    - 規定ラウンド数の具体的な値は未決定。
- 銃弾を当てた箇所に応じて得点
    - 頭　100点
    - 顔　20点
    - 首　20点
    - 心臓　30点
    - 胴　10点
    - 腕,足　5点
    - 股間　-100点（ペナルティ）
- 後抜きで3倍の得点
    - 相手が銃を持ってるときに銃を抜くとフラグを付与。
- 合計スコアは常に画面左上に表示

# ✅ リプレイ対応（NEW）
プレイヤーの**入力履歴（マウス位置・ボタン）**を記録
再生時は記録された入力データを元に再現
必要に応じてキャラクターの状態同期（再生とネット対戦との整合性も意識）

# ✅ オンライン対戦
- 配布先
    - 正式版はSteamでの配布を目指す。
    - テスト版はitch.ioで配布する。
    - 可能ならブラウザでも遊べるようにする。早期に動作検証する。
- 対戦相手の探し方
    - v1は実装範囲を抑え、部屋コードを相手に共有して参加する1対1対戦とする。
    - ランクマッチはv2以降の検討事項とする。
- 通信方式（暫定）
    - Netcode for GameObjects（NGO）を想定して進める。
    - 接続・中継はUnity Multiplayer ServicesとRelayを候補とする。採用は未確定。
    - Steamworksを対戦の必須条件にしない。
    - テストで操作感などに問題があれば、原因と改善可能性を確認し、別方式も検討する。
- 早期テスト
    - 過去にStart()の同期ミスで構造が崩れた経験があるため、2人接続で初期化と開始の同期を確認する。
    - 遅延を加え、ホストとクライアントを交代して照準・抜銃・回避・発砲の反応を比較する。
    - ブラウザでの接続とマウス操作を確認する。
- 未決定
    - 発砲時点の命中判定に使う相手の姿勢の時刻と、結果を確定する判定権限。
    - 通信遅延がある場合の発砲順・同時発砲・相撃ちの扱い。
    - ブラウザ版とデスクトップ版の相互対戦を必須にするか。
